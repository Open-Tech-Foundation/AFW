# Deployment

An AFW app compiles to **static files** — a hashed JS bundle, CSS, and (optionally)
pre-rendered HTML — so today you build once and serve `dist/` from any static host or
CDN, with no runtime to operate.

AFW is a fullstack framework. Alongside the static output, it can run a server:
an app-owned server entry renders routes per request (SSR) and mounts your
[API routes](/docs/routing/api-routes) at their file paths (`route.{js,ts}` works in
any folder, conventionally `app/api/`), and answers [server functions](/docs/server-functions).

Choose the output that fits your app:

- **[Production Build](/docs/deployment/build)** — a single-page app: one `index.html`
  shell plus the bundle. The client renders every route. Best for app-like sites behind
  auth or with mostly dynamic content.
- **[Static Generation](/docs/deployment/static-generation)** — additionally
  prerenders routes to their own HTML files through an explicit build step. Best for content and
  marketing sites that need SEO and instant first paint.
- **[Server](/docs/deployment/server)** — run a server for per-request SSR and
  [API routes](/docs/routing/api-routes), through a server entry or runtime adapter. Best for
  fullstack apps that need server logic.
- **[Fetch handler](/docs/deployment/fetch-handler)** — deploy the generated handler to any
  Fetch-native runtime (Workers, Deno, Bun edge, etc.): static assets plus middleware, API
  routes, loader data and server functions, with platform bindings via `context.env`.

<Callout type="tip" title="Same bundle, more HTML">
  SSG doesn't change your app — it runs the same components through a string renderer at
  build time, then the client bundle adopts that markup on load ([Hydration](/docs/deployment/hydration)).
  You can start with a plain build and add a prerender target later.
</Callout>

## Hosting

`dist/` is self-contained static output. Point any of these at it:

- A static host / CDN (Netlify, Vercel, Cloudflare Pages, GitHub Pages, S3 + CloudFront).
- Any web server (nginx, Caddy) serving the folder.

For a **single-page** build, configure the host to fall back to `index.html` for unknown
paths so client-side routes resolve. A fully **static-generated** site needs no fallback
— generated routes have their own HTML files. Configure the host to return your
404 page for paths that were not generated.

## Running a server

If your app uses SSR, [API routes](/docs/routing/api-routes), loaders or
[server functions](/docs/server-functions), run a server instead of serving `dist/`
statically:

- **Vite + Node** — `vite build` emits `dist/server/index.js`; run it with
  `node dist/server/index.js`.
- **esdev** — build the app's server target, which serves the generated `@afw/server`
  handler, and run it with `esdev dist/server.js`.
- **Any Fetch runtime** (Workers, Deno, Bun) — export the same handler as the
  runtime's `fetch`.

See **[Server](/docs/deployment/server)** and **[Fetch handler](/docs/deployment/fetch-handler)**.
