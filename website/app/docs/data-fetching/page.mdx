# Data Fetching

Data reaches a page in one of two ways, one per side of the network.

| | [Route loaders](/docs/data-fetching/route-loaders) | [`resource()`](/docs/data-fetching/resource) |
| --- | --- | --- |
| Runs | On the server: at build time, per request, or before a client navigation | In the browser, after the page renders |
| Written as | A `loader.{js,ts}` file next to a `page.*` | A call in a component or page |
| Result | The reactive `router.data` | Reactive `data`, `loading` and `error` |
| In the server HTML | Yes | No: the server renders the loading state |
| Can import secrets and database drivers | Yes: never ships to the browser | No: call a [server function](/docs/server-functions) instead |

- **Use a loader** for content the server should render: SEO, first paint, shareable pages.
- **Use `resource()`** for per-user or interaction-driven data: search results, dashboards, data behind a click.
- **Writes** go through [server functions](/docs/server-functions), which refetch loaders and resources with `invalidate()`.

## In this section

- **[Route Loaders](/docs/data-fetching/route-loaders):** the `loader` file, `router.data`, the loader context, where loaders run, and registering them in the browser entry.
- **[Loader Errors & Redirects](/docs/data-fetching/loader-errors):** `notFound()`, redirects and refusals with a thrown `Response`, and other errors.
- **[`resource()`](/docs/data-fetching/resource):** fetching in the browser, reactive sources, abort and stale responses, refetch and invalidation.
- **[Loading States](/docs/data-fetching/pending):** `<Pending>` for one fallback over many resources, refetch views, delays, and error routing.
