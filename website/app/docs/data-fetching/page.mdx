# Data Fetching

Two primitives, one per side of the network:

- **Route loaders** — a server-only `loader.{js,ts}` file next to a page runs
  *before* the page renders (at build time, per request, or on navigation) and
  its result reaches the page as the reactive `router.data`.
- **`resource()`** — a client-side primitive that wraps a fetcher in signals:
  `{ data, loading, error, refetch }`, with abort and stale-response handling.

Rule of thumb: content the server should render (SEO, first paint) → a loader;
per-user or interaction-driven data → `resource()`.

## Route loaders

A loader is the data analogue of an [API route](/docs/routing/api-routes): a
**plain server module** sibling to the `page.*` it feeds. It never ships to the
browser, so database drivers and secrets are safe to import.

```
app/todos/page.jsx        → the page
app/todos/loader.js       → its loader
app/items/[id]/loader.ts  → dynamic params work like pages
```

```js
// app/todos/loader.js
export default async function loader({ params, query, request, locale }) {
  return { items: await db.todos.list() }; // JSON-serializable data
}
```

The page reads the reactive **`router.data`**, exactly like `router.params`:

```jsx
// app/todos/page.jsx
import { router } from "@opentf/afw";

export default function Todos() {
  return (
    <ul>
      {(router.data ? router.data.items : []).map((t) => (
        <li key={t.id}>{t.title}</li>
      ))}
    </ul>
  );
}
```

### The loader context

| Field | What it is |
| --- | --- |
| `params` | Route params from `[param]` / `[...rest]` segments, percent-decoded (catch-alls as arrays). |
| `query` | Parsed query-string object, one value per name (a repeated name keeps its last value; use `new URL(request.url).searchParams.getAll(name)` for all). Empty at SSG time. |
| `request` | The live `Request` when supplied by a request server; `undefined` at SSG prerender. |
| `locale` | The active locale (path-prefix i18n), or `null`. |
| `locals` | Per-request bag from [middleware](/docs/routing/middleware) (`context.locals`); `{}` when no middleware runs (e.g. SSG prerender). |

### Where it runs

- **Static builds (`esdev build`)** — the project's prerender script runs loaders at build time: the data is baked into the prerendered
  HTML **and** written as a static `<path>/__data.json` file next to each page,
  so client-side navigation works on a purely static host — no server needed.

- **Request servers** — the generated [`@afw/server`](/docs/deployment/server) handler
  runs loaders per request before rendering and serves the same data endpoint for client
  navigation. With Vite, `vite build` ships it in `dist/server`; with esdev, the app's
  server target imports it.

On first paint the data arrives inline with the server HTML (no extra request);
on SPA navigation the router fetches `<path>/__data.json` **before** committing
the navigation, so the page never renders with missing data and stale responses
from superseded navigations are discarded. `__data.json` is a reserved filename.

### Not found & errors

```js
import { notFound } from "@opentf/afw/server";

export default function loader({ params }) {
  const post = db.posts.find(params.id);
  if (!post) notFound(); // → the 404 page, with HTTP 404
  return post;
}
```

### Redirects and refusals

A loader can throw a `Response`, as API routes and server functions can:

```js
export default async function loader({ params, locals }) {
  const post = await db.posts.find(params.id);
  if (post && post.slug !== params.slug) {
    throw new Response(null, { status: 301, headers: { location: `/posts/${post.id}/${post.slug}` } });
  }
  if (post?.private && post.owner !== locals.user?.id) throw new Response(null, { status: 403 });
  return post;
}
```

- On a server render, the thrown `Response` is the page's response.
- On a client navigation, a redirect navigates to its target, replacing the history
  entry; another status is reported as a failed data fetch.
- Use it for decisions that need the loader's data: a canonical URL, a moved record,
  access to this one item. Sign-in checks for a whole section belong in
  [middleware](/docs/routing/middleware), once.
- When middleware redirects a data request (an auth guard), the router loads the page
  in full, so the server's redirect applies.

### Other errors

Any other thrown error is a 500. On the client, a failed data fetch is reported
(`phase: "data"`) and the navigation still commits with `router.data`
undefined — pages should treat "no data" as a valid state.

### Register loaders in the browser entry

Pass the patterns of pages with loaders to `mountApp` so the router knows which
data endpoints to fetch. `@afw/routes` discovers them from the `loader.*` files:

```js entry.js
import { mountApp } from "@opentf/afw";
import { guard, loaderRoutes, pages } from "@afw/routes";

mountApp({ pages, guard, loaders: loaderRoutes, target: document.getElementById("app") });
```

- `loaderRoutes` lists route patterns only (`"/todos"`, `"/items/[id]"`); the loader
  modules never reach the browser.

### Current limits

- Loaders are **page-level** (no layout loaders yet).
- A query-dependent loader needs a request server — static `__data.json` files are
  rendered with an empty query.
- Streaming is future work (see the
  [roadmap](https://github.com/Open-Tech-Foundation/afw/blob/main/docs/roadmap.md)).
  For writes, use [server functions](/docs/server-functions).
- A `loader.*` without a sibling `page.*` is a build error.
- Dynamic routes still need `getStaticPaths` on the page to prerender.

## `resource()`

For client-side async data, `resource()` formalizes the fetch-into-signals
pattern — components stay synchronous, and the view renders the resource's
reactive states:

```jsx
import { resource, router } from "@opentf/afw";

export default function UserProfile() {
  const user = resource(
    () => router.params.id, // reactive source — re-fetches when it changes
    async (id, { signal }) => {
      const response = await fetch(`/api/users/${encodeURIComponent(id)}`, { signal });
      if (!response.ok) throw new Error(`Request failed: ${response.status}`);
      return response.json();
    },
  );

  return (
    <div>
      {user.error ? <p>Failed: {user.error.message}</p> :
       user.loading ? <p>Loading…</p> :
       user.data ? <h1>{user.data.name}</h1> : <p>No user selected.</p>}
    </div>
  );
}
```

- `resource(fetcher)` fetches once; `resource(source, fetcher)` re-fetches when
  the reactive `source` changes; `{ initial }` seeds `data`.
- Each run aborts the previous run's `AbortController` (the fetcher receives
  `{ signal }`) and late, out-of-order resolutions are discarded.
- A rejection sets `error` and keeps the last good `data`; the next success
  clears it. `refetch()` re-runs manually.
- A `source` returning `null`/`false` pauses fetching (conditional resources).
- [`invalidate()`](/docs/server-functions#refetch-after-an-action) refetches every live
  resource and reloads the page's loader data; `invalidate(listTodos)` only the
  resources that called that server function.
- During SSG/SSR nothing fetches and `loading` stays `true`, so the prerendered
  HTML shows your loading branch and [hydration](/docs/deployment/hydration) stays aligned.
