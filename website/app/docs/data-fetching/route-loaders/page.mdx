# Route Loaders

A loader is the data analogue of an [API route](/docs/routing/api-routes): a
**plain server module** sibling to the `page.*` it feeds. It never ships to the
browser, so database drivers and secrets are safe to import.

```
app/todos/page.jsx        → the page
app/todos/loader.js       → its loader
app/items/[id]/loader.ts  → dynamic params work like pages
```

```js
// app/todos/loader.js
export default async function loader({ params, query, request, locale }) {
  return { items: await db.todos.list() }; // JSON-serializable data
}
```

The page reads the reactive **`router.data`**, exactly like `router.params`:

```jsx
// app/todos/page.jsx
import { router } from "@opentf/afw";

export default function Todos() {
  return (
    <ul>
      {(router.data ? router.data.items : []).map((t) => (
        <li key={t.id}>{t.title}</li>
      ))}
    </ul>
  );
}
```

## The loader context

| Field | What it is |
| --- | --- |
| `params` | Route params from `[param]` / `[...rest]` segments, percent-decoded (catch-alls as arrays). |
| `query` | Parsed query-string object, one value per name (a repeated name keeps its last value; use `new URL(request.url).searchParams.getAll(name)` for all). Empty at SSG time. |
| `request` | The live `Request` when supplied by a request server; `undefined` at SSG prerender. |
| `locale` | The active locale (path-prefix i18n), or `null`. |
| `locals` | Per-request bag from [middleware](/docs/routing/middleware) (`context.locals`); `{}` when no middleware runs (e.g. SSG prerender). |

## Where it runs

- **Static builds (`esdev build`)** — the project's prerender script runs loaders at build time: the data is baked into the prerendered
  HTML **and** written as a static `<path>/__data.json` file next to each page,
  so client-side navigation works on a purely static host — no server needed.

- **Request servers** — the generated [`@afw/server`](/docs/deployment/server) handler
  runs loaders per request before rendering and serves the same data endpoint for client
  navigation. With Vite, `vite build` ships it in `dist/server`; with esdev, the app's
  server target imports it.

On first paint the data arrives inline with the server HTML (no extra request);
on SPA navigation the router fetches `<path>/__data.json` **before** committing
the navigation, so the page never renders with missing data and stale responses
from superseded navigations are discarded. `__data.json` is a reserved filename.

## Register loaders in the browser entry

Pass the patterns of pages with loaders to `mountApp` so the router knows which
data endpoints to fetch. `@afw/routes` discovers them from the `loader.*` files:

```js entry.js
import { mountApp } from "@opentf/afw";
import { guard, loaderRoutes, pages } from "@afw/routes";

mountApp({ pages, guard, loaders: loaderRoutes, target: document.getElementById("app") });
```

- `loaderRoutes` lists route patterns only (`"/todos"`, `"/items/[id]"`); the loader
  modules never reach the browser.

## Current limits

- Loaders are **page-level** (no layout loaders yet).
- A query-dependent loader needs a request server — static `__data.json` files are
  rendered with an empty query.
- Streaming is future work (see the
  [roadmap](https://github.com/Open-Tech-Foundation/afw/blob/main/docs/roadmap.md)).
  For writes, use [server functions](/docs/server-functions).
- A `loader.*` without a sibling `page.*` is a build error.
- Dynamic routes still need `getStaticPaths` on the page to prerender.
