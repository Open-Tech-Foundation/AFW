# Installation

AFW has two official workflows. Both compile the same components and `app/` routes.

| Workflow | Choose it when |
| --- | --- |
| **esdev + ES-Runtime** | You want the single-binary, capability-secured ES-Runtime toolchain. |
| **Vite + Node** | Your server code needs the Node ecosystem: ORMs, database drivers, native addons such as `sharp`, or Node hosting. |

## Install esdev

Install ES-Runtime's **esdev** development binary before creating a project.
Use esdev 0.17 or newer and a package manager such as pnpm.

<Tabs tabs={installTabs} />

Verify the installation before continuing:

```bash
esdev --version
```

See the official [installation guide](https://esrun.opentechf.org/docs/install)
for version pinning, upgrades and custom install locations.

## Create a project

```bash
esdev create my-app
```

Follow the prompts to choose a template, language and package manager.

## Non-interactive usage

Specify your choices with flags for scripts or CI:

```bash
esdev create my-app --template=spa --language=js --package-manager=pnpm
```

Use `--language=ts` for TypeScript and `esdev create --help` for supported options.

Available templates:

| Template | Purpose |
| --- | --- |
| `spa` | A browser app with file-based routing and client rendering. |
| `fullstack` | A browser app with a server entry for APIs, middleware and request rendering. |
| `docs` | An MDX docs/blog site with prerendered HTML, navigation and search. |
| `library` | A source package of reusable components compiled by its consumers. |

Template files are embedded in esdev; package versions are resolved while scaffolding.
Each template writes its `esdev.json`, entry files and `dev`/`build`/`test` scripts.

## Vite and Node

Create a project with npm (or `pnpm create`, `yarn create`, `bun create`):

```bash
npm create @opentf/afw my-app
```

Follow the prompts, or pass the choices as flags:

```bash
npm create @opentf/afw my-app -- --template=fullstack --language=ts
```

| Template | Purpose |
| --- | --- |
| `spa` | A browser app with file-based routing and client rendering. |
| `fullstack` | An SPA plus API routes, middleware and loaders on a Node server. |
| `ssr` | Pages rendered on a Node server per request and hydrated in the browser. |
| `ssg` | Every page prerendered to static HTML at build time. |

Each project has `dev`, `build`, `test` (Vitest) and either `start` (the built Node
server) or `preview` scripts. TypeScript projects add `typecheck`. Server code runs
on Node in development and production, so any npm package works there.
