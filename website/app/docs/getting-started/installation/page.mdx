# Installation

AFW has two official workflows. Both compile the same components and `app/` routes, and
both create the same projects: the same questions, the same `app/` and `tests/`. Only the
toolchain's own files differ.

| Workflow | Choose it when |
| --- | --- |
| **esdev + ES-Runtime** | You want the single-binary, capability-secured ES-Runtime toolchain. |
| **Vite + Node** | Your server code needs the Node ecosystem: ORMs, database drivers, native addons such as `sharp`, or Node hosting. |

## Create a project

| Workflow | Command | Needs |
| --- | --- | --- |
| esdev + ES-Runtime | `esdev create my-app` (pick **AFW**) | esdev 0.28 or newer, [installed below](#install-esdev) |
| Vite + Node | `npm create @opentf/afw my-app` (or `pnpm`/`yarn`/`bun create`) | Node 24 or newer |

Both ask the same questions:

| Template | Questions |
| --- | --- |
| `app` | How pages render by default · whether it has a server · styling · language |
| `docs` | Whether it has a blog · language |
| `library` | Styling · language |

## The `app` template's choices

**How should pages render by default?** The answer goes to `app/_config.js`; any folder
can [change it with its own](/docs/routing/rendering).

| Choice | Pages | Good for |
| --- | --- | --- |
| **Client** (default) | Rendered in the browser | Apps behind a login |
| **Server** | Rendered per request, then hydrated | Content sites, search, anything with SEO |
| **Static** | Built once at build time, then hydrated | Marketing sites, docs, blogs |
| **Mixed** | Server by default, with a prebuilt `/about` and a client `/dashboard` | Sites that need all three; copy the examples |

The other choices:

- **Server**: API routes, middleware, loaders and [server functions](/docs/server-functions).
  Asked for Client and Static; Server and Mixed always have one.
- **Styling**: plain CSS or [Tailwind CSS](/docs/core-concepts/styling#tailwind-css), also
  for `library`.
- **Language**: TypeScript (default) or JavaScript, for every template.
- **Blog** (`docs`): posts with RSS and Atom feeds. Off unless you ask for it.

## Non-interactive usage

| Workflow | Example |
| --- | --- |
| esdev | `esdev create my-app --template=app --render=mixed --styling=tailwind --language=ts` |
| Vite | `npm create @opentf/afw my-app -- --template app --render mixed --tailwind --language ts` |

- `--render`: `client`, `server`, `static` or `mixed`. The names of earlier releases still
  work: `spa` is client, `ssr` is server, `ssg` is static.
- `--server` / `--no-server`, `--blog` / `--no-blog`.
- esdev: `esdev create --help` lists the options; Vite: `npm create @opentf/afw -- --help`.
- The Vite template names of earlier releases (`spa`, `fullstack`, `ssr`, `ssg`) still work
  as shorthands for `app`.

## What a project contains

| | esdev + ES-Runtime | Vite + Node |
| --- | --- | --- |
| Toolchain config | `esdev.json` (+ `server.js` with a server, `ssg.js` for a static site) | `vite.config.js` |
| Scripts | `dev`, `build`, `test`, `start` or `preview`; `typecheck` with TypeScript | the same |
| Tests | `tests/ui/` (components) and `tests/server/` (API routes); `esdev test` | the same files; Vitest |
| Server code runs on | ES-Runtime | Node, so any npm package works |

Tests import their API from `@opentf/afw-test/test`, so the same files run under either
runner. See [Project Structure](/docs/getting-started/project-structure) for each file.

## Install esdev

Install ES-Runtime's **esdev** development binary before creating an esdev project.

<Tabs tabs={installTabs} />

Verify the installation before continuing:

```bash
esdev --version
```

See the official [installation guide](https://esrun.opentechf.org/docs/install)
for version pinning, upgrades and custom install locations.
