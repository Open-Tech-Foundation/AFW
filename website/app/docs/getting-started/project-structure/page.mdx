# Project Structure

The layouts below match the projects both scaffolders write (`esdev create` and
`npm create @opentf/afw`); see [Installation](/docs/getting-started/installation).

- Apps and docs sites share the `app/` routing layout; libraries ship source components
  and keep a small preview app.
- `app/` and `tests/` are the same in both workflows. Only the toolchain files differ:
  `esdev.json` (with `server.js` or `ssg.js`) or `vite.config.js`.
- The trees show JavaScript; TypeScript projects use `.ts`/`.tsx` and add `tsconfig.json`.

## App

A client-rendered app, the `app` template's default:

```text
my-app/
├─ app/
│  ├─ _config.js      # how pages render: { render: "client" }
│  ├─ layout.jsx      # wraps every page
│  ├─ page.jsx        # route: /
│  ├─ Counter.jsx     # a component
│  ├─ about/
│  │  └─ page.md      # route: /about, written in Markdown
│  └─ global.css
├─ tests/
│  └─ ui/
│     └─ Counter.test.js   # component test
├─ public/            # optional: files served at the site root
├─ entry.js           # client bootstrap
├─ index.html         # mount point + module script
├─ esdev.json         # esdev: compiler plugin and build targets
├─ vite.config.js     # Vite: the AFW plugin (instead of esdev.json)
└─ package.json
```

## App with a server

The **Server**, **Mixed** and (when you add one) **Client** or **Static** choices add
server code, bundled separately and never shipped to the browser:

```text
my-app/
├─ app/
│  ├─ _config.js        # { render: "server" }
│  ├─ _middleware.js    # runs for every request
│  ├─ api/
│  │  └─ hello/
│  │     └─ route.js    # API endpoint: GET /api/hello
│  ├─ todos/
│  │  ├─ page.jsx
│  │  ├─ loader.js      # data → router.data, on the server
│  │  └─ todos.server.js   # server functions the page calls
│  └─ …                 # layout, page, about/ as above
├─ tests/
│  ├─ server/
│  │  └─ api.test.js    # API route test, no DOM
│  └─ ui/
│     └─ Counter.test.js
├─ server.js            # esdev: the server entry (Vite builds its own)
└─ …
```

**Mixed** adds two folders that override the default, to copy from:

```text
app/
├─ about/
│  ├─ _config.js     # { render: "static" }: built once
│  └─ page.md
└─ dashboard/
   ├─ _config.js     # { render: "client" }: rendered in the browser
   ├─ loader.js      # still runs on the server
   └─ page.jsx
```

See [Rendering](/docs/routing/rendering) for how `_config.js` works.

## Documentation site

```text
my-docs/
├─ app/
│  ├─ _config.js          # { render: "static" }: every page prerendered
│  ├─ page.jsx            # landing page
│  ├─ layout.jsx
│  ├─ docs/
│  │  ├─ layout.jsx       # docs shell (sidebar + TOC)
│  │  ├─ _meta.js         # sidebar order + labels
│  │  ├─ page.mdx         # /docs
│  │  ├─ getting-started/page.mdx
│  │  └─ guides/writing-pages/page.mdx
│  └─ global.css
├─ tests/ui/Home.test.js
├─ afw.config.js          # site URL, docs/blog sections (@opentf/afw-docs)
├─ ssg.js                 # esdev: the release prerender step
├─ entry.js
├─ index.html
└─ package.json
```

With a blog, `app/blog/` holds the post list and the posts; see
[afw-docs → Blog](/packages/afw-docs/blog).

## Library

```text
my-lib/
├─ index.js           # package entry: export each component
├─ src/
│  └─ Counter.jsx
├─ tests/ui/Counter.test.js
├─ app/page.jsx       # preview app for `dev` (not published)
├─ entry.js
├─ index.html
└─ package.json
```

See [Library template](/docs/getting-started/library-template) for publish and
consumption details.

## Special files

Files the toolchain recognizes beyond ordinary components. Extensions `.js`, `.ts`,
`.jsx`, and `.tsx` are interchangeable unless noted.

### Routing (App & Docs)

| File | Role |
| --- | --- |
| `page.jsx` / `page.mdx` | A route. The folder path is the URL (`app/about/page.jsx` → `/about`). |
| `layout.jsx` | Wraps every route below it; nests with the folder tree. |
| `404.jsx` | Rendered when no route matches. |
| `loading.jsx` | The [loading view](/docs/routing/loading-and-errors) for the pages beneath its folder, during navigation and while their resources load. |
| `error.jsx` | The [error view](/docs/routing/loading-and-errors) for the pages beneath its folder, when the loader, the page or a resource fails. |
| `route.js` | An [API endpoint](/docs/routing/api-routes). The folder is the URL (`app/api/hello/route.js` → `/api/hello`). A folder holds a `page.*` or a `route.*`, never both. |
| `loader.js` | A [route loader](/docs/data-fetching/route-loaders) sibling to a `page.*`. Runs server-side before the page renders; its return value is `router.data`. Requires a matching `page.*` in the same folder. |
| `(group)/` | A [route group](/docs/routing/route-groups): organizes pages and gives them a layout, middleware or error page, without being part of the URL. |
| `layout.loader.js` | A [layout loader](/docs/data-fetching/route-loaders#layout-loaders) sibling to a `layout.*`: data for every page beneath that layout, merged into `router.data`. |
| `_middleware.js` | [Middleware](/docs/routing/middleware) for its folder and everything nested under it (pages, API, loader data, SSR). |
| `_config.js` | How the pages in its folder and below it render (`server`, `static` or `client`); the nearest one wins. See [Rendering](/docs/routing/rendering). |
| `_meta.js` | Docs sidebar order and labels for a folder (`@opentf/afw-docs`). Supports `.js`, `.mjs` and `.json` today. |

### Project root

| File / folder | Role |
| --- | --- |
| `esdev.json` | Compiler plugins, build targets, output locations and development settings. |
| `vite.config.js` | Vite workflow: the AFW plugin (`@opentf/vite-plugin-afw`) and test settings. |
| `server.js` | esdev, apps with a server: the server entry around the generated `@afw/server`. |
| `ssg.js` | esdev, static sites: the prerender step a release build runs. |
| `tests/ui/`, `tests/server/` | Component tests (with a DOM) and server tests (API routes, without one). |
| `entry.js` | Client bootstrap: imports @afw/routes and calls mountApp. |
| `index.html` | The HTML shell with an explicit module script. Your entry mounts into `#app`; esdev bundles the module script. |
| `public/` | Static assets copied to `dist/` at build time and served at the site root (`public/favicon.svg` → `/favicon.svg`). Overrides generated files when names collide (e.g. a hand-written `public/robots.txt`). |
| `afw.config.js` | Optional for SPA/fullstack (`site.url`, `i18n`). Required for docs/blog production builds and drives `@opentf/afw-docs` (navbar, search, feeds). See [Configuration](/docs/configuration). |
| `dist/` | Build output — created by `esdev build` or `vite build`. Not checked in; safe to delete and rebuild. |

Every other PascalCase `.jsx`/`.tsx` file under `app/` is a reusable component — no
registration needed (see [Components](/docs/core-concepts/components)).

## Conventions

- Route pages and layouts need a default export. Reusable components can use named or default exports.
- Components are PascalCase (`UserCard.jsx`).
- You never import `$state`, `onMount`, etc. — the compiler injects them.

<Callout type="info" title="TypeScript">
  TypeScript is the default at the scaffold prompt: `.tsx` pages, `.ts` API routes,
  loaders and `_config.ts`, and a `tsconfig.json`. Docs sites keep
  `afw.config.js` and `_meta.js` as JavaScript — the toolchain reads those today.
</Callout>
