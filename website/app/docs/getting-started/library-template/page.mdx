# Library Template

Component libraries can ship JSX/TSX source from `index.js`. Apps compile that source
with their own AFW plugin, so the library does not bundle a second copy of the
framework.

- **esdev:** `esdev create my-lib --template=library --package-manager=pnpm`. The
  project compiles components for tests and includes a rendering test that
  `esdev test --dom` runs.
- **Vite:** `npm create @opentf/afw my-lib -- --template=library` (add
  `--styling=tailwind` for Tailwind classes). It includes a preview app
  (`npm run dev`) and a Vitest test.

## Using a library in a Vite app

- Install it next to `@opentf/afw`. Nothing to configure.
- `@opentf/vite-plugin-afw` compiles every dependency that declares `@opentf/afw` (as a
  peer or a dependency): in the dev server, in server and prerender builds, and in
  Vitest.
- A library that uses Tailwind classes needs `@source "../node_modules/my-lib";` in the
  app's stylesheet, since Tailwind does not scan `node_modules`.

## Package entry

```js index.js
export { default as Counter } from "./src/Counter.jsx";
```

Include `index.js` and `src/` in the package's `files` list, and make `@opentf/afw`
a peer dependency. Install the runtime, plugin and test helpers for development:

```bash
pnpm add -D @opentf/afw @opentf/esdev-plugin-afw @opentf/afw-test
```

## Sample component

```jsx src/Counter.jsx
export default function Counter(props) {
  let count = $state(props.initial ?? 0);
  return <button type="button" onclick={() => count++}>Count: {count}</button>;
}
```

## Rendering tests

The library's `esdev.json` compiles components for client rendering and turns
route discovery off, since a library has no `app/` folder. The
[Testing Setup](/packages/afw-test/setup) module registers cleanup:

```json esdev.json
{
  "plugins": [{
    "module": "@opentf/esdev-plugin-afw",
    "options": { "target": "csr", "routes": false }
  }],
  "test": { "setup": ["@opentf/afw-test/setup"] }
}
```

```js tests/counter.test.js
import { expect, test } from "runtime:test";
import { render } from "@opentf/afw-test";
import { Counter } from "../index.js";

test("updates after a click", async () => {
  const { getByRole } = render(Counter, { initial: 2 });
  const button = getByRole("button", { name: "Count: 2" });
  button.click();
  expect(button.textContent).toBe("Count: 3");
});
```

```bash
esdev test --dom
```

Use `--browser` for full user-event interaction sequences. Publishing source and
publishing a compiled library are different workflows; see esdev's official
[library build guide](https://esrun.opentechf.org/esdev/build/library) if consumers
need precompiled output.
