# Tutorial

Build a notes page from scratch, in about fifteen minutes:

- a component with reactive state
- a loader that renders the notes on the server
- typed server functions to add and delete notes, validated with Zod
- `invalidate()` to refresh the page after a change
- a component test
- a production build that runs on Node

The tutorial uses the **Vite + Node** workflow and JavaScript. On esdev the `app/` code
is the same; only the server entry differs (see [Server Setup](/docs/deployment/server)).

## 1. Create the app

```bash
npm create @opentf/afw@latest my-notes -- --template app --render ssr --language js
cd my-notes
npm install zod
npm run dev
```

- `--render ssr` renders pages on the server per request and hydrates them in the
  browser. It always includes a Node server.
- The starter already has a home page, an About page and a todos example. Open
  `http://localhost:5173`.
- Zod validates the server functions' input. Any
  [Standard Schema](https://standardschema.dev) library works.

## 2. Write the server functions

A `*.server.js` file runs only on the server. Its `query()` and `action()` exports
become functions the browser can call; everything else in it stays on the server.

```js app/notes/notes.server.js
import { action, query } from "@opentf/afw/server";
import { z } from "zod";

// In memory for the tutorial: a real app keeps notes in its database.
const notes = [{ id: 1, text: "Read the AFW docs" }];
let nextId = 2;

export const listNotes = query(async () => notes);

export const addNote = action(z.object({ text: z.string().trim().min(1, "Write something first") }), async ({ text }) => {
  const note = { id: nextId++, text };
  notes.push(note);
  return note;
});

export const deleteNote = action(z.object({ id: z.number() }), async ({ id }) => {
  const index = notes.findIndex((note) => note.id === id);
  if (index !== -1) notes.splice(index, 1);
});
```

- `query()` is for reads, `action()` for writes.
- With a schema, the input is validated on the server before the function runs. Invalid
  input never reaches it: the call fails with the schema's issues.
- Each function answers at its own URL under `/notes/`, so a `_middleware.js` in
  `app/notes/` would guard them too. See [Server Functions](/docs/server-functions).

## 3. Load the notes on the server

A loader next to a page runs on the server before the page renders. Its result is the
page's `router.data`.

```js app/notes/loader.js
import { listNotes } from "./notes.server.js";

export default async function loader({ locals }) {
  return { notes: await listNotes(undefined, { locals }) };
}
```

- A server function called from server code runs directly, with no HTTP request.
- Pass the `locals` your middleware set, so the function sees the same user.

## 4. Build the form component

```jsx app/notes/NoteForm.jsx
export default function NoteForm({ save }) {
  let text = $state("");
  let error = $state("");

  async function submit(event) {
    event.preventDefault();
    try {
      await save(text);
      text = "";
      error = "";
    } catch (e) {
      error = e.issues?.[0]?.message ?? e.message;
    }
  }

  return (
    <form onsubmit={submit}>
      <input value={text} oninput={(e) => (text = e.target.value)} placeholder="New note" aria-label="New note" />
      <button type="submit">Add</button>
      {error ? <p role="alert">{error}</p> : null}
    </form>
  );
}
```

- `$state` makes `text` and `error` reactive: assigning them updates only the DOM that
  reads them.
- The component compiles to a Custom Element. `save` is a prop, set by the page.
- A rejected server function call carries the schema's `issues`.

## 5. Build the page

```jsx app/notes/page.jsx
import { invalidate, router } from "@opentf/afw";
import NoteForm from "./NoteForm.jsx";
import { addNote, deleteNote } from "./notes.server.js";

export const metadata = { title: "Notes" };

export default function Notes() {
  const notes = $derived(router.data?.notes ?? []);

  async function save(text) {
    await addNote({ text });
    await invalidate(); // reload this page's loader data
  }

  async function remove(id) {
    await deleteNote({ id });
    await invalidate();
  }

  return (
    <section>
      <h1>Notes</h1>
      <ul>
        {notes.map((note) => (
          <li>
            {note.text} <button onclick={() => remove(note.id)}>Delete</button>
          </li>
        ))}
      </ul>
      <NoteForm save={save} />
    </section>
  );
}
```

- The page imports `addNote` from `notes.server.js`, but the browser gets a small fetch
  stub, not the server code. Calls are typed and need no URL.
- `invalidate()` refetches the page's loader data after a change, so the list updates.
- Add the page to the navigation in `app/layout.jsx`:

```jsx app/layout.jsx
import { Link } from "@opentf/afw";

export default function Layout({ children }) {
  return (
    <>
      <nav>
        <Link href="/">Home</Link>
        <Link href="/about">About</Link>
        <Link href="/todos">Todos</Link>
        <Link href="/notes">Notes</Link>
      </nav>
      <main>{children}</main>
    </>
  );
}
```

Open `/notes`: the list is in the server-rendered HTML, and adding or deleting a note
updates it without a reload. An empty note shows "Write something first", from the
schema.

<Callout type="tip" title="Prefetching">
  Hover the Notes link: `<Link>` loads the page's code and its loader data before the
  click, so the navigation has nothing left to wait for.
</Callout>

## 6. Test the component

```js tests/NoteForm.test.js
import { expect, test, vi } from "vitest";
import { render, userEvent } from "@opentf/afw-test";
import NoteForm from "../app/notes/NoteForm.jsx";

test("saves the typed note and clears the input", async () => {
  const save = vi.fn(async () => {});
  const { getByRole } = render(NoteForm, { save });
  const user = userEvent.setup();
  await user.type(getByRole("textbox", { name: "New note" }), "Buy milk");
  await user.click(getByRole("button", { name: "Add" }));
  expect(save).toHaveBeenCalledWith("Buy milk");
  expect(getByRole("textbox").value).toBe("");
});

test("shows the server's validation message", async () => {
  const save = async () => {
    throw Object.assign(new Error("Invalid input"), { issues: [{ message: "Write something first" }] });
  };
  const { getByRole, findByRole } = render(NoteForm, { save });
  await userEvent.setup().click(getByRole("button", { name: "Add" }));
  expect((await findByRole("alert")).textContent).toBe("Write something first");
});
```

```bash
npm test
```

- `render` mounts a component in a DOM; the queries and `userEvent` come from Testing
  Library.
- The test passes a fake `save`, so it needs no server.

## 7. Build and run in production

```bash
npm run build
npm start
```

- `npm run build` writes the browser assets to `dist/client` and a Node server to
  `dist/server`.
- `npm start` runs `node dist/server/index.js`. `PORT` and `HOST` set where it listens.
- To deploy: copy the project to any Node 22+ host, run `npm ci --omit=dev` (the server
  imports `zod` from `node_modules`), `npm run build`, then `npm start`.
