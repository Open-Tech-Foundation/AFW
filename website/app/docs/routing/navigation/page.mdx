# Navigation

## The Link component

`<Link>` performs client-side navigation — no full page reload. It renders a real
anchor, so modified clicks (new tab, etc.) still work.

```jsx
import { Link } from "@opentf/afw";

<Link href="/about">About</Link>
```

### Prefetching

`<Link>` warms its route before the click, so the navigation has nothing left to wait
for:

- What is warmed: the page and layout chunks, and the route's
  [loader data](/docs/data-fetching), which the navigation then reuses (once, within
  30 seconds).
- `prefetch="intent"` (default): on hover, focus or touch.
- `prefetch="viewport"`: when the link scrolls into view, for a few key links.
- `prefetch="none"`: never.
- Skipped for `reload` links, MPA navigation, and when the browser asks to save data
  (`Save-Data`).
- `prefetch(path)` from `@opentf/afw` warms a route from code.
- [`invalidate()`](/docs/server-functions#refetch-after-an-action) drops prefetched
  data, which may be stale.

```jsx
<Link href="/dashboard" prefetch="viewport">Dashboard</Link>
<Link href="/export" prefetch="none">Export</Link>
```

## The router

The global `router` is reactive — read its fields directly (no `.value`):

```jsx
import { router } from "@opentf/afw";

<nav class={router.pathname === "/" ? "home" : ""}>…</nav>
```

| Member | Description |
| --- | --- |
| `router.pathname` | Current path (reactive). |
| `router.params` | Dynamic route params (reactive). |
| `router.query` | Parsed query string, one value per name (reactive). A repeated name keeps its last value. |
| `router.searchParams` | The full `URLSearchParams`, for repeated names: `router.searchParams.getAll("tag")` (reactive). |
| `router.locale` | Active locale when i18n is enabled, else `null` (reactive). |
| `router.push(path)` | Navigate, pushing a history entry. |
| `router.replace(path)` | Navigate, replacing the current entry. |

<Callout type="tip" title="Reactive reads">
  Reading `router.pathname` inside a binding (an attribute or `{}` expression) updates
  the UI automatically when the route changes.
</Callout>

## Localized navigation

When i18n is enabled, the locale lives in the URL path and `<Link>` automatically keeps
navigation in the active locale. Build a localized URL yourself with `localizePath` — handy
for a language switcher:

```jsx
import { Link, localizePath, router } from "@opentf/afw";

// The current page under another locale:
<Link href={localizePath(router.pathname, "fr")}>Français</Link>
```

See the [Locale Routing guide](/packages/afw-i18n/routing) for the full model
(`prefix_except_default`, per-locale SSG/SSR, detection), and the
[`@opentf/afw` API reference](/docs/core#routing) for `localizePath`, `setLocale`, and the
other locale exports.
