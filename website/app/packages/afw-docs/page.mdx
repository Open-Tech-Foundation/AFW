# @opentf/afw-docs

The documentation theme that powers this very site. It layers a themed shell —
navbar, sidebar, table of contents, breadcrumbs, prev/next — over your MDX content,
and generates the navigation tree from the file system at build time.

```bash
pnpm add @opentf/afw-docs
```

<Callout type="info" title="A package, not a fork">
  Your docs site is an ordinary AFW app that imports afw-docs. The same compiler,
  router, and SSG build it — there is no separate documentation runtime.
</Callout>

## Content is MDX

`.mdx` files are routes: Markdown plus JSX components. Each page starts with
frontmatter; `title` feeds the sidebar, breadcrumbs, and `<title>`.

```mdx
---
title: Reactivity
description: Signal-based state.
---

# Reactivity

Prose, `inline code`, and components side by side.

import { Callout } from "@opentf/afw-docs";

<Callout type="tip">Mix components into Markdown freely.</Callout>
```

Fenced code is highlighted at build time, and every code block gets a copy button
automatically.

## Build setup

Install `@opentf/esdev-plugin-afw` and use the
[SSG build configuration](/docs/deployment/static-generation). Register the docs
plugins explicitly in `esdev.json`, following
[Configuration](/packages/afw-docs/configuration#build-plugins), and import the
theme from your entry stylesheet:

```css app/global.css
@import "@opentf/afw-docs/theme";
```

Adding `docs` or `blog` to `afw.config.js` supplies settings; it does not register
plugins or create the prerender script.

## The shell

Wrap your docs routes in `DocsLayout`. That's the whole layout — it sources the
generated sidebar itself:

```jsx
// app/docs/layout.jsx
import { DocsLayout } from "@opentf/afw-docs";
import config from "../../afw.config.js";

export default function Layout(props) {
  return (
    <DocsLayout config={config.docs}>
      {props.children}
    </DocsLayout>
  );
}
```

The build plugin scans every top-level folder under `app/` and resolves
`@opentf/afw-docs/nav` to a `{ "/<dir>": tree }` map; `DocsLayout` reads it and shows the
branch for the current route. So **any** folder with a layout like this becomes its own
documentation section — `app/api` → `/api`, with its own sidebar — and they all share the
same traits ([last updated](/packages/afw-docs/configuration), search, prev/next).

Continue with [Components](/packages/afw-docs/components) and
[Configuration](/packages/afw-docs/configuration).
